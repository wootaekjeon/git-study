# new-feature-issue

새 기능 요청을 **승인 가능한 이슈 초안**으로 바꾸고, 승인되면 이슈를 만든 뒤 워크트리에서 구현을 시작한다.

이슈 생성은 GitHub에 공개로 남는 행동이므로, 사용자가 초안을 확인하기 전에는 `gh issue create`를 실행하지 않는다. 라벨 목록과 색상은 [references/labels.md](references/labels.md)에 있다. **초안을 쓰기 전에 반드시 읽는다.**

## 워크플로

### 1. 기능 요청 감지와 정보 수집

요청에서 아래 세 가지를 뽑는다.

- **목적:** 왜 필요한지 (무엇을 해결하는지)
- **요구사항:** 무엇을 해야 하는지 (입력, 출력, 동작)
- **완료 조건:** 어떻게 되면 끝난 것인지 (검증 가능한 문장)

정보가 부족하면 초안을 만들기 전에 한두 가지만 짧게 묻는다. 추측으로 요구사항을 채우지 않는다.

### 2. 중복 확인

```bash
gh issue list --search "<핵심 키워드>" --state all --limit 10
```

비슷한 이슈가 있으면 번호와 제목을 보여주고, 새로 만들지 기존 이슈에 붙일지 묻는다.

### 3. 라벨 준비 확인

```bash
gh label list --limit 100
```

references/labels.md의 라벨 중 저장소에 없는 것이 있으면 목록으로 보여주고 **생성 여부를 확인**한다. 승인되면 아래 명령으로 만든다. `--force`는 이미 있는 라벨을 덮어쓰기만 하므로 여러 번 실행해도 중복이 생기지 않는다.

```bash
gh label create "<이름>" --color "<색상코드>" --description "<설명>" --force
```

기존 영문 라벨(`enhancement`, `bug`, `documentation` 등)은 삭제하지 않는다.

### 4. 이슈 초안 제시 → 승인

아래 형태로 보여주고 승인을 받는다.

```
이슈 초안

제목: 버스 노선별 승하차 히트맵 추가
라벨: 기능, 시각화, 대기
중복 확인: 없음

---
## 배경 / 목적
...

## 요구사항
- ...

## 완료 조건
- [ ] ...

## 참고
- read_data.py, data/bus_alighting.xlsx
---

이대로 이슈를 만들까요?
```

**라벨 규칙**
- 기본 라벨: 1개 (`기능`, `버그`, `문서` 중 택1)
- 주제 라벨: 0~2개 (`데이터`, `분석`, `시각화`, `모델`, `파이프라인`)
- 진행상태 라벨: 1개, 생성 시 항상 `대기`

**제목 규칙**
- 60자 이내, 명사형이나 "~추가", "~개선"으로 끝나는 짧은 문장
- 이슈 번호는 제목에 넣지 않는다

**본문 규칙**
- 템플릿의 네 섹션을 모두 쓰되, 정보가 없는 "참고"는 생략한다
- 확인하지 않은 수치나 기간은 쓰지 않는다

### 5. 이슈 생성

승인되면 본문을 임시 파일로 저장하고 생성한다. 작업 파일은 스크래치패드에 둔다.

```bash
gh issue create --title "<제목>" --body-file "<임시 md 경로>" --label "기능,시각화,대기"
```

생성 결과에서 이슈 번호와 URL을 가져와 사용자에게 알려준다. 라벨이 제대로 붙었는지 `gh issue view <번호> --json number,title,labels,url`로 확인한다.

### 6. 워크트리에서 작업 시작

사용자가 작업을 이어가길 원하면 `EnterWorktree`로 워크트리를 만든다.

- 이름: `feat-<이슈번호>-<짧은-영문-슬러그>` (예: `feat-12-bus-heatmap`)
- 기준 브랜치: `main`. 다른 브랜치를 쓰려면 사용자에게 먼저 묻는다.

워크트리에 들어간 뒤에는 이슈의 완료 조건을 기준으로 구현한다. 완료 조건을 하나씩 체크할 때마다 이슈 본문을 고칠지는 묻는다.

## 하지 않는 것

- push와 PR 생성은 사용자가 요청할 때만 한다.
- 라벨 삭제, 기존 이슈 수정·닫기는 요청 없이 하지 않는다.
- `--no-verify` 등으로 훅을 우회하지 않는다.
- 승인 전에 `gh issue create`를 실행하지 않는다.

## 참고

- 사용자가 라벨이나 제목을 직접 지정하면 그 선택을 따른다. 단, 진행상태 라벨은 생성 시 `대기`로 고정한다.
- 여러 기능을 한 번에 요청하면 기능마다 이슈를 따로 만든다. 한 이슈에 여러 기능을 묶지 않는다.
